# Acceptance Tests MVP 1

## Backend сценарии

- Пользователь регистрируется по телефону и получает dev access token.
- Пользователь обновляет профиль.
- Пользователь добавляет друга.
- Пользователь создаёт группу.
- Пользователь создаёт сбор.
- Пользователь добавляет обычного участника.
- Пользователь добавляет гостя без регистрации.
- Пользователь добавляет ребёнка с долей `0.5`.
- Пользователь назначает платёжного ответственного.
- Пользователь добавляет расход вручную.
- Пользователь указывает одного или нескольких плательщиков расхода.
- Пользователь запускает расчёт.
- Backend сохраняет новую версию расчёта.
- Backend возвращает расчёт по участникам.
- Backend возвращает расчёт по платёжным ответственным.
- Backend возвращает минимизированный transfer plan.
- Backend возвращает объяснение суммы.
- Участник подтверждает расчёт по своей доле.
- Участник создаёт спор по своей доле или доле гостя/ребёнка, за которого отвечает.
- Организатор принимает, отклоняет или закрывает спор пересчётом.
- Участник отправляет ручную оплату с комментарием/proof URL.
- Получатель или организатор подтверждает либо отклоняет ручную оплату.
- Backend пишет audit log для спорных и платёжных действий.
- Backend создаёт уведомления по review, спорам и ручным оплатам.

## Расчётный движок

- Все делят поровну.
- Один человек не участвует в категории.
- Участник имеет долю `0.5`.
- Есть несколько плательщиков.
- Есть фиксированная сумма.
- Есть округление.
- Сумма `0`.
- Все исключены из расхода.
- Несколько категорий.
- Минимизация переводов.
- Пользователь платит за двоих.
- Пользователь платит за гостя.
- Ребёнок `0.5` доли.
- Гость исключён из алкоголя.
- Один расход оплачен двумя людьми.
- Расчёт по платёжным ответственным.
